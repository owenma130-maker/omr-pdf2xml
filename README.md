# omr-pdf2xml

**乐谱 PDF → MusicXML，附带一份可以自己复核的成绩单。**

大多数 OMR（光学乐谱识别）工具只给你一个结果，不告诉你它对不对。
这个项目多做一件事：**拿纸面当标准答案，给输出打一份分。**

```
$ omr check 乐谱.pdf --musicxml 输出.musicxml
====================================================================
  自检报告 —— 判据全部来自纸面/PDF 自身
====================================================================
  裁判          : PDF 文本层印刷小节号
  输出 part 数  : 19
  输出小节/part : 132
  输出音符      : 8245（<chord/> 成员 340）
  输出音高      : 6493   休止 1744

      页      印刷首号         本页应有小节数   印刷号
      3         8               5   [8]
      4        13               4   [13]
      5        17               5   [17]
      ...
====================================================================
```

---

## 这个项目是什么 / 不是什么

**是**：一个 OMR 前端 + 一套独立裁判。

- **识别**这一层目前用 [Audiveris](https://github.com/Audiveris/audiveris)（AGPL-3.0）完成 —— 它是"眼睛"。
- **本项目的贡献**是它后面和周围的那一层：小节切分的修正、多小节休止展开、
  音高/时值/记号的导出、以及**独立裁判**（告诉用户错在哪、错多少）。

**不是**：一个已经能脱离 Audiveris 的完整自研引擎。见下面「已知限制」。

---

## 独立裁判：判据从哪来

四条判据，**全部来自纸面或 PDF 自身**，不是"再识别一遍"：

| 判据 | 来源 | 能回答什么 |
|---|---|---|
| **印刷小节号** | PDF 文本层里印在每个 system 左边距的号（斜体 8pt，坐标 `x≤110, y≥50`） | 我们切出的小节和纸上印的对不对得上 |
| **相邻页首号相减** | 同上，两页相减 | 这一页**应该**有几小节（精确，零图像处理） |
| **多小节休止粗横杠** | PDF 矢量图形：描边 ≥2pt 的水平线，且压在该行谱表的**中间那条线**上 | "休止 N 小节"被漏掉多少 |
| **进/出计数** | 我们自己的链路 | 有没有丢音符、丢小节 |

**诚实原则：读不出就说读不出。**

- **数字 PDF**（打谱软件直接导出的）：小节号就在文本层里，**零误差**直接读。
- **扫描件**（没有文本层）：退到**定向 OCR** —— 实测发现一条很稳的常数：
  `system 谱表顶线 − 号的底边 = 48~52 px`，所以只 OCR `[顶线−122, 顶线−38]`
  这一小窗，比 OCR 整条左边距准得多。
- **两条路都读不出**：报告明确写 `裁判: ★ 没有裁判`，而不是编一个数字出来。

### 自检报告里能看到的对齐

```
★ 逐 system 对齐（纸上印的号 vs 我们的号）: 10/10 命中
 sheet system     印刷     我们   判定
     1      2     17     17   OK
     1      3     29     29   OK
     ...
     2      3     94     94   OK
```

## 安装

```bash
pip install -e .                 # 核心（裁判 + 导出）
```

完整管线（PDF 直接出 MusicXML）还需要 **Audiveris**（Java 程序，独立安装）：

```
Windows: 默认装在 C:\Program Files\Audiveris\Audiveris.exe
Linux/macOS: 见 Audiveris 官方仓库
```

---

## 用法

```bash
# 1) 自检报告（推荐先跑：它告诉你这份输入里有没有"标准答案"）
omr check 乐谱.pdf --musicxml 输出.musicxml

# 2) 从一个已有的 .omr 导出 MusicXML
omr omr2xml 乐谱.omr -o 输出.musicxml

# 3) 完整管线：PDF → Audiveris → .omr → MusicXML
omr pdf2xml 乐谱.pdf -o 输出.musicxml --audiveris "C:\Program Files\Audiveris\Audiveris.exe"
```

## 准确性（实测，不是宣传）

| 材料 | 类型 | 结果 |
|---|---|---|
| 单声部扫描件（3 页，源 PDF 自带重复页） | 扫描 | 输出 103 小节；**逐 system 首号对齐 10/10**（定向 OCR 读出的印刷号）；Render 100%、拍号守恒 100%、丢音符 0 |
| 81 页材料 · 指挥总谱段（28 页 / 18 声部） | 数字 PDF | **132/132 小节**（与印刷号逐页一致） |
| 81 页材料 · 19 份分谱 | 数字 PDF | 121~132 小节；其中 3 份正好 132 |

> 口径说明：以上"小节数"一律指**与纸面印刷小节号对齐**，不是和任何商业软件的输出比。
> 参考：某商业 OMR 在同类材料上的历史输出，把同一页输出了两遍、把另一页整页漏掉；
> 在同类总谱上 20 个声部合计只出了 29 小节。

## ★ 已知限制（请先读这一节）

1. **"看清谱面"这一步还在 Audiveris 手里。** 本项目目前**不能**脱离它运行。
   我们试过换成 `homr`（Apache-2.0，许可证更干净），结果落在一款商业 OMR 的同一水平
   （同一份单声部扫描件：真值 73 小节，`homr` 出 62，那款商业软件也出 62）。
   Audiveris 的**几何**（谱表 / 小节线 / 小节切分）是它唯一明显强的一层。
2. **单线谱表（打击乐）**：Audiveris 整页读不出（`No system found`）。
   自研的单线谱表检测能补出音符，但尚未接入导出。
3. **符杠召回低**：`.omr` 里几乎没有符杠信息（`beam-stem` 关系 0 条），
   目前靠一个检测器补，召回约 16 组 / 参考值 38 组。
4. **多小节休止的展开位置偶有偏差**：数量算得准（由印刷号相减得出），
   但"插在哪一小节"偶尔会差 1~6 个。
5. **扫描件没有自检**：纸面没印小节号时，本工具**给不出**正确性判据，只会如实说明。
6. **多声部总谱在"各页声部数不一致"时**会把声部并错（本项目已知）。
